0. EXECUTIVE VERDICT (READ FIRST)
================================================================================

Best ERP for "all Nepal business natures" is NOT 40 mega-modules.
It is:

  SHARED FINANCIAL CORE (ledger truth + Nepal tax)
       + REUSABLE CAPABILITY ENGINES (CAP-*)
       + INDUSTRY PACKS (PACK-*) that compose engines + COA + docs + reports
       + NATURE ONBOARDING that enables packs without re-implementation

Current product baseline (2026-07 research of this repo):
  STRONG  — trading cycle, journals, stock, POS, VAT/TDS hooks, CBMS code,
            cost centres, budgets, fixed assets page, payroll basics, Orbix AI
  THIN    — BOM (shell), production (manual), serials/MCY/period-lock/CBMS
            dashboard (orphan or weakly routed), maker-checker, year-end
  MISSING — construction RA/retention, fund/donor accounting, project PSA,
            metal-weight jewellery, hotel folio, fee demand, loan portfolio

Governing rule for "best offering":
  Close Wave 0 (Foundation Hardening) before any new vertical theatre.
  Then ship capability engines that unlock MANY natures at once.
  Vertical UI is configuration + documents + reports on top of engines.

Success picture (done for a nature):
  Company selects nature → pack enables → COA/docs/tax map ready →
  Top-5 daily tasks trainable in one session → VAT/TDS/CBMS path clean →
  Ask MokXya drafts only for production_approved rows of that nature →
  Month-end close without Excel side books for that nature's core flow.

2. NON-NEGOTIABLE DESIGN PRINCIPLES
================================================================================

P1. Ledger truth first — every ops document posts deterministic journals
    via domain engines (not LLM totals).
P2. Nepal statutory before ops theatre — VAT 13%, sales/purchase registers,
    TDS, fiscal FY (Shrawan–Ashadh), BS/AD dates, IRD e-billing path.
P3. Compose, don't fork — one company, one COA; packs add accounts,
    voucher types, reports, dashboards, validations.
P4. Finish thin before new — wire orphan pages, close stubs, then CAP-*.
P5. Phased rollout — finance → inventory/trade → vertical engines →
    regulated packs. No big-bang all-40.
P6. Standard over custom — if >30% of a nature's Must-haves need one-off
    customization, we are missing an engine; build the engine.
P7. Explicit AI confirm — draft → preview → edit → confirm token → post.
P8. Honest packaging — do not sell PACK-FIN-* / PACK-NGO until gate closed.
P9. Dual calendar — Bikram Sambat + AD everywhere fiscal matters.
P10. Audit-proof by default — soft delete, reason codes, attachments,
     immutable invoice numbers, period lock.

----------------------------------------------------------------------
CAP-CORE — Shared Financial Core
----------------------------------------------------------------------
Depends: none
MVP: Company setup, COA, parties, tax masters, journals, sales/purchase/
     returns, receipt/payment/contra, TB/PL/BS, aging, audit trail,
     period lock, FY close, attachments, roles
Full: recurring/reversing, maker-checker, budgets, fixed asset lifecycle,
      multi-branch consolidation lite
DoD: New company → opening → sale/purchase/receipt/payment → TB balances;
     period lock blocks posting; audit trail on edit
Natures: ALL

----------------------------------------------------------------------
CAP-TAX-NP — Nepal Tax & IRD Path
----------------------------------------------------------------------
Depends: CAP-CORE
MVP: VAT 13%/exempt/zero, sales & purchase registers, credit/debit note
     tax linkage, TDS natures + certificates tracking, FY invoice series,
     BS/AD dates, soft-delete/no hard delete on tax docs
Full: CBMS real-time/scheduled sync + retry log + dashboard; IRD annex
      export formats; Schedule-8 digital payment rebate support when
      rules verified; e-TDS summaries; software listing evidence pack
DoD: Sample month: registers reconcile to ledger VAT control accounts;
     CBMS sync status honest (success/fail/retry); invoice reprint marked
Natures: ALL commercial; mandatory for VAT-registered

NOTE: IRD listing / CBMS thresholds change — Compliance Owner maintains
verified rule pack. AI never invents current thresholds or rates.

7.4 Multi-Nature Composition Rules
----------------------------------
1. One Primary nature drives default COA + dashboard + Top-5 training.
2. Secondary natures enable extra packs; duplicate accounts merge by code.
3. Conflicting valuation policies → company-level single policy (warn).
4. Fund packs + trading packs allowed only with fund tags mandatory on
   expense vouchers (NGO trading desk pattern).
5. PACK-MULTI required if >2 secondary natures or explicit group reporting.
6. Invoice series remain company-unique (never per-nature renumber chaos).
